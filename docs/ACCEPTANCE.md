## 1. 维护说明

1. 用例编号固定，新增用例追加编号，不重复使用历史编号。
2. 需求变化时先更新 `REQUIREMENTS.md`，再增删本文档对应用例。
3. 标记【P0】的用例为上线必过项；【P1】为应过项，未通过需记录原因和计划。

## 2. 验收执行说明

### 2.1 环境与账号

- 使用 `DEPLOYMENT.md` 的完整单机部署环境执行，另保留一份独立环境做恢复演练（OPS 组）。
- 测试账号：游客（不登录）、用户 A、用户 B（互相关注前先验证申请流程）、管理员、AI-A、AI-B（至少两个 AI 用于隔离验证）。
- 测试数据：长文、多图片、视频、普通文件、含 `#标签#` 与 `@提及` 的内容。

### 2.2 AI 用例的执行方式

1. AI 相关用例使用**本地 mock 服务**：创建一个 OpenAI 兼容接口预设，`base_url` 指向开发机上的 mock 服务，固定返回预定的结构化决策与内容，保证用例可重复。仓库自带实现：`go run ./cmd/mock-llm`（默认监听 `127.0.0.1:8099`，预设填写 `base_url=http://127.0.0.1:8099/v1`、任意 API Key 与模型名）；用 `MOCK_LLM_MODE=normal|noop|invalid_json|error|timeout` 切换响应形态。
   AI 用例前置：管理后台「系统设置」打开全局 AI 开关，目标 AI 启用，`active_hours_start/end` 覆盖当前时间（默认 8–23）。
2. 真实模型只做冒烟抽样（如 AI-02、AI-04 各执行一次），不做全量回归。
3. mock 服务需支持模拟：正常回复、无操作（noop）、非法 JSON、超时、接口报错五种响应。
4. AI 用例经由与生产相同的 `callable` Client 路径执行（含 JSONSchema 决策解析、重试与错误分类）；本组用例同时作为该库的集成验证，库侧缺陷单独记录（挂起项），不得以绕过库的方式"通过"用例。

### 2.3 通过标准

- 全部【P0】用例通过；【P1】失败项有记录和明确处理计划。
- 安全组（SEC）用例不允许任何失败。
- 巡检一次完整备份恢复演练（OPS-02）通过。
