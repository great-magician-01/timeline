## 2. 验收执行说明

### 2.1 环境与账号

- 使用 `DEPLOYMENT.md` 的完整单机部署环境执行，另保留一份独立环境做恢复演练（OPS 组）。
- 测试账号：游客（不登录）、用户 A、用户 B（互相关注前先验证申请流程）、**超级管理员**（空库首个注册账号，用于初始化与授权/撤销）、**普通管理员**（由超管从用户 A/B 中授权产生，用于越权用例）、普通用户（未授权账号，同时作为私信非成员用例的用户 C）、AI-A、AI-B（至少两个 AI 用于隔离验证）。
- 初始化相关用例（ENV-13、AUTH-07、AUTH-08）需要**空库环境**：使用全新数据库或隔离 schema，不得在常规验收库上清空数据；已有部署升级场景单独验证。
- 测试数据：长文、多图片、视频、普通文件、含 `#标签#` 与 `@提及` 的内容。

### 2.2 AI 用例的执行方式

1. AI 相关用例使用**本地 mock 服务**：创建一个 OpenAI 兼容接口预设，`base_url` 指向开发机上的 mock 服务，固定返回预定的结构化决策与内容，保证用例可重复。仓库自带实现：`go run ./cmd/mock-llm`（默认监听 `127.0.0.1:8099`，预设填写 `base_url=http://127.0.0.1:8099/v1`、任意 API Key 与模型名）；用 `MOCK_LLM_MODE=normal|noop|invalid_json|error|timeout|search|search_twice|search_error|search_auth_error` 切换响应形态；搜索模式会模拟 `web_search` 工具调用及 `/v1/tools/search` 结果/错误。
   AI 用例前置：管理后台「系统设置」打开全局 AI 开关，目标 AI 启用，`active_hours_start/end` 覆盖当前时间（默认 8–23）。
2. 真实模型只做冒烟抽样（如 AI-02、AI-04 各执行一次），不做全量回归。
3. mock 服务需支持模拟：正常回复、无操作（noop）、非法 JSON、超时、接口报错、搜索工具调用、搜索 404 与搜索 401 等响应。
4. AI 用例经由与生产相同的 `callable` Client 路径执行（含 JSONSchema 决策解析、重试与错误分类）；本组用例同时作为该库的集成验证，库侧缺陷单独记录（挂起项），不得以绕过库的方式"通过"用例。

### 2.5 目标架构改造后的回归项

结构改造（G1–G8）完成后，除本清单原有功能用例外，还需回归：

1. **路由与策略**：`/api/v1` 路由数量/方法/路径与改造前一致；非 GET 必须属于写策略；`/admin` 必须为 Admin/SuperAdmin 策略；`grant-admin`/`revoke-admin` 必须为 SuperAdminWrite；CSRF 挂载与错误码不变。
2. **CSRF 全链路**：游客注册/登录、会话写接口、缺失或不匹配 `X-CSRF-Token` 的 403 `csrf_failed` 行为不变。
3. **事务边界**：发帖（帖子+草稿+版本+附件+标签+搜索+提及+作业）、评论/点赞（事件+计数+通知）、用户停用与会话吊销、授权/撤销（角色+审计）必须同一事务成功或整体回滚，不残留半成品且审计与业务同生共死。
4. **时间**：写接口显式传时间；`information_schema` 中除 `schema_migrations.applied_at` 外无业务 `now()` 默认值；`TZ=UTC` 下日界/租约/退避测试通过。
5. **结构守卫**：`go test ./internal/architecture` 通过；`*gin.Context`、SQL 关键字与 `time.Now()` 只出现在允许位置。

## 4. 账号与认证（AUTH）

| 编号 | 场景 | 步骤要点 | 预期结果 |
| --- | --- | --- | --- |
| AUTH-01【P0】 | 注册 | 用唯一用户名+邮箱注册；重复用户名/邮箱再注册；关闭注册开关后再注册 | 注册成功并可登录；重复返回明确错误；关闭后注册接口返回 403 |
| AUTH-02【P0】 | 双标识登录 | 分别用用户名、邮箱登录；连续输错密码 | 两种标识均可登录；连续失败触发 429 限频 |
| AUTH-03【P0】 | 会话与 CSRF | 先调用 `/auth/csrf` 获取游客令牌，再登录并检查 Cookie 属性；登出后调 `/auth/me`；去掉 `X-CSRF-Token` 分别发一次登录和登录后写请求 | 会话 Cookie 为 HttpOnly；登出后 401；登录和登录后写请求缺少 CSRF token 均返回 403 `csrf_failed`；`/auth/me` 可刷新当前会话令牌 |
| AUTH-04【P0】 | 停用即时生效 | 用户 A 保持登录，管理员停用 A；A 刷新页面并尝试发文；再启用 A | 停用后既有会话立即失效，写操作返回 `account_suspended`；公开内容仍可只读访问；启用后恢复 |
| AUTH-05【P0】 | 密码重置 | A 在两个浏览器登录，管理员重置 A 密码；A 修改自己密码 | 重置后原会话全部失效；自行改密后其他会话失效、当前会话保留；任何位置都查不到明文密码 |
| AUTH-06【P0】 | AI 无法登录 | 用 AI 的账号尝试密码登录 | 登录被拒绝；AI 在页面带 AI 标识 |
| AUTH-07【P0】 | 首注册成为超级管理员 | 空库环境下先关闭注册开关再注册首个账号；开启开关注册第二个账号；再次关闭开关尝试注册第三个账号 | 首个账号在开关关闭时仍注册成功且返回 `role=admin`、`is_super_admin=true`，**不自动登录**，登录页提示已成为超级管理员；第二个账号为 `role=user` 且不含 `is_super_admin`；第三个账号（已有用户且开关关闭）返回 403；`/auth/me`、登录、管理端用户列表/详情返回 `is_super_admin`，公开资料与搜索接口不返回该字段 |
| AUTH-08【P0】 | 并发首注册唯一超管 | 空库环境下并发提交多个不同用户名/邮箱的注册请求 | 只有 1 个账号成为超级管理员，其余成为普通用户（同键冲突返回 409 `duplicate`）；数据库中 `is_super_admin=true` 的记录始终为 1 条（部分唯一索引兜底）；重启服务后状态不变 |
